## Phase 0: Research

### TD-11: Magic number 100 in TokenManager

**Decision**: Add `private const DEFAULT_TOKEN_WINDOW = 100;` to `TokenManager`.

**Rationale**: The value 100 appears twice as a default parameter in `getLeftTokens()` and `getProcessedTokens()`. It also appears implicitly in `getAll()` which calls `getLeftTokens()` with no argument. A named constant documents the intent (it is a debug inspection window, not a business limit) and makes future tuning a one-line change.

**Alternatives considered**: `const` at class level vs. hard-coded default. Named constant wins for discoverability and because the value is shared between two methods.

**Note on `getNextAfterFirstFoundElement`**: That method calls `getLeftTokens(1000)` — a *different* value, intentionally larger. It must NOT use `DEFAULT_TOKEN_WINDOW`. Leave it as-is (or as TD-17 addresses separately).

### strict_types output

**Decision**: Modify `ProgramEmitter::emit()` to prepend `declare(strict_types=1);` after `<?php`.

**Rationale**: `strict_types=1` is a PHP best practice that prevents silent type coercions and aligns with how the compiler source files themselves are written. PHireScript's type system is explicit — the generated PHP should enforce the same discipline. Without it, passing a string where `int` is expected silently coerces instead of throwing `TypeError`.

**Where**: `ProgramEmitter::emit()` sets `$code['init'] = "<?php\n\n"`. Change to `"<?php\n\ndeclare(strict_types=1);\n\n"`. The `declare` statement must come before `namespace` (handled by `processEntireCode()` which places `init` first).

**Alternatives considered**: Adding it in `FileCompiler::compileFile()` post-processing — rejected because the emitter is the canonical place for PHP output structure.

**Blast radius**: All `.psc` snapshot files become stale. Must run `php phirescript/bin/snapshot` after the change to regenerate them. Test cases that assert exact PHP output in `CaseValidation.php` may need updating if they match `<?php` without `declare`.

**Validation impact**: Generated PHP files currently pass `php -l` lint check in `FileCompiler`. With `declare(strict_types=1)` added, the lint check still passes (valid PHP). Runtime behavior of test PHPUnit cases may surface latent type mismatches in sandbox cases — those should be fixed, not suppressed.

### TD-8 status

**Decision**: Close as resolved-by-refactor. No code change needed.

**Rationale**: The original TD-8 described two `foreach` loops in `Binder.php` (monolithic, pre-refactor). The current code uses the CompilerPass discovery pattern: `TypeRegistrationBinder` (order: 1) does the first pass, and `ProgramBinder` (order: 2) dispatches all remaining binders per statement. These are separate classes with single responsibilities — the "duplication" is gone. Backlog entry TD-8 can be marked closed.

// Before
